## 📌 Overview

**AI Interview Preparation & ATS Resume Builder** is a full-stack Generative AI web application that helps job seekers prepare for interviews with confidence. Users upload their resume and paste a job description; the system uses Google Gemini to generate a structured interview preparation report covering match score, skill gaps, technical and behavioral questions, and a preparation plan. It can also produce an ATS-optimized version of the resume, downloadable as a PDF.

The project follows a layered, feature-based architecture on both frontend and backend, with secure cookie-based JWT authentication and token blacklisting.

---

## ✨ Key Features

| Feature | Description |
|---------|-------------|
| 🔐 **Secure Authentication** | Register/Login with JWT stored in HTTP-only cookies; logout invalidates tokens via a blacklist |
| 📄 **Resume Upload & Parsing** | Upload PDF resumes (Multer) and extract text for analysis |
| 🧠 **AI Interview Report** | Gemini-generated report with match score, strengths, and gaps against the job description |
| 🎯 **Skill Gap Detection** | Clear breakdown of missing vs. matched skills with severity |
| ❓ **Tailored Questions** | Role-specific technical and behavioral questions with answer guidance |
| 🗓 **Preparation Plan** | Day-wise roadmap to close identified gaps |
| 🕘 **Report History** | View all past reports and recently generated ones from the dashboard |
| 📥 **AI Resume PDF** | ATS-optimized resume content generated by AI and rendered to PDF with Puppeteer |
| 🛡 **Protected Routes** | Frontend route guards and backend auth middleware |
| ✅ **Structured AI Output** | Zod schemas validate every AI response before it is stored |

## 🛠 Tech Stack

**Frontend**
- React.js (Vite), React Router, Axios

- Node.js, Express.js

## 🚀 Getting Started

### Prerequisites

- Node.js **v18 or higher**
- npm or yarn
- A [MongoDB Atlas](https://www.mongodb.com/atlas) cluster
- A [Google Gemini API key](https://aistudio.google.com/)

### Installation

**1. Clone the repository**
```bash
git clone https://github.com/Bhumika955/Genai-fullstack-app.git
cd Genai-fullstack-app
```

**2. Set up the backend**
```bash
cd Backend
npm install
cp .env.example .env     # then fill in your values
npm run dev
```

**3. Set up the frontend** (in a new terminal)
```bash
cd Frontend
npm install
npm run dev
```

**4. Open the app**

| Service | URL |
|---------|-----|
| Frontend | http://localhost:5173 |
| Backend | http://localhost:3000 |

## 🔑 Environment Variables

Create a `.env` file inside `backend/`:

| Variable | Description | Example |
|----------|-------------|---------|
| `PORT` | Server port | `3000` |
| `MONGO_URI` | MongoDB Atlas connection string | `mongodb+srv://...` |
| `JWT_SECRET` | Secret for signing JWTs | `a-long-random-string` |
| `GEMINI_API_KEY` | Google Gemini API key | `AIza...` |
| `CLIENT_URL` | Frontend origin for CORS | `http://localhost:5173` |

> ⚠️ Never commit your `.env` file. Add it to `.gitignore`.

## 📡 API Reference

Base URL: `/api`

### Authentication

| Method | Endpoint | Auth | Description |
|--------|----------|:----:|-------------|
| `POST` | `/auth/register` | ❌ | Create a new account |
| `POST` | `/auth/login` | ❌ | Login and receive JWT cookie |
| `GET` | `/auth/logout` | ✅ | Logout and blacklist the token |
| `GET` | `/auth/get-me` | ✅ | Get the current user's profile |

**Example: Register**
```http
POST /api/auth/register
Content-Type: application/json

{
  "username": "bhumika",
  "email": "bhumika@example.com",
  "password": "securePassword123"
}
```

### Interview Reports

| Method | Endpoint | Auth | Description |
|--------|----------|:----:|-------------|
| `POST` | `/interview` | ✅ | Generate a report (multipart: `resume`, `jobDescription`, `selfDescription`) |
| `GET` | `/interview` | ✅ | List all reports of the user |
| `GET` | `/interview/:id` | ✅ | Get a single report |
| `POST` | `/interview/resume/pdf/:id` | ✅ | Generate and download the AI-optimized resume PDF |

**Sample response (report)**
```json
{
  "matchScore": 78,
  "technicalQuestions": [{ "question": "...", "intention": "...", "answer": "..." }],
  "behavioralQuestions": [{ "question": "...", "intention": "...", "answer": "..." }],
  "skillGaps": [{ "skill": "Docker", "severity": "medium" }],
  "preparationPlan": [{ "day": 1, "focus": "...", "tasks": ["..."] }]
}
```

## 🔐 Authentication Flow

1. User submits credentials → server verifies and signs a **JWT**
2. Token is set as an **HTTP-only cookie** (not accessible to JavaScript)
3. **Auth middleware** validates the token and checks it against the blacklist on each protected request
4. On **logout**, the token is stored in a blacklist collection so it cannot be reused
5. Frontend **protected routes** redirect unauthenticated users to the login page

## 🧠 AI Pipeline

```
Resume PDF + Job Description
          │
          ▼
   Text extraction (Multer + parser)
          │
          ▼
   Prompt construction → Gemini API
          │
          ▼
   Zod schema validation (structured JSON)
          │
          ▼
   Save report to MongoDB → render on UI
          │
          ▼ (on demand)
   Gemini generates ATS-friendly resume HTML
          │
          ▼
   Puppeteer renders HTML → PDF → download
```

## 🛡 Security Considerations

- Passwords hashed with **bcrypt**
- JWT stored in **HTTP-only cookies** to mitigate XSS token theft
- **Token blacklisting** prevents reuse after logout
- **CORS** restricted to the configured client origin
- File uploads limited by **type and size**
- Secrets managed via **environment variables**

## 🧰 Troubleshooting

| Problem | Fix |
|---------|-----|
| CORS error in browser | Ensure `CLIENT_URL` matches the frontend origin and `withCredentials: true` is set in Axios |
| Cookie not being set | Check `sameSite`/`secure` cookie options for your environment |
| MongoDB connection fails | Whitelist your IP in Atlas Network Access and verify `MONGO_URI` |
| Puppeteer fails on server | Install required Chromium dependencies or use `--no-sandbox` in hosted environments |
| Gemini response invalid | Check `GEMINI_API_KEY` and ensure the Zod schema matches the prompt's expected output |
